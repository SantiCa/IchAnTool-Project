# M2.1.2 interval lookup and cumulative Data table expansion

## Scope and acceptance

This phase measures ten Show more actions, up to 10,400 rendered rows, and optimises interval lookup for the
Data table and its full CSV export. The native table and paging behaviour remain the default. It does not
introduce viewport rendering; cumulative DOM results guide a separately authorised phase.

- Use the M2.1 fixtures at 2,000, 20,000 and 100,000 total rows, one warm-up and five measured trials each.
  Record each expansion's row count and latency, final scrolling/selection, full export and sampled RSS.
- Reduce the 100,000-row median full CSV latency by at least 25% against the same-tool V0.109 baseline.
- Require identical full CSV fingerprints and exact interval-object equivalence with the original first-match
  predicate, including overlaps, gaps, half-open endpoints, invalid bounds and nonnumeric query values.
- Preserve row order, counts, editing/restoration, native selection and existing repository/browser checks.
  Introduce no performance thresholds in CI.

### CSV formatter follow-up acceptance

The authorised follow-up targets `core.js::toCSV`, the largest JavaScript self-time site in the export profile.
Use the same fixtures, ten expansions, one warm-up, five measured repetitions and separate profiles. Repeat
V0.109 with the V0.110 benchmark tools in an isolated checkout, then measure the candidate with identical tools.
Keep the existing target: at least 25% lower median full CSV latency at 100,000 rows against V0.109.
Require identical complete CSV fingerprints at all three sizes and exact formatter equivalence for integers,
six-decimal rounding, IEEE-754 boundaries, missing values, text quoting and spreadsheet-formula escaping.
Do not change the CSV format, scientific calculations, table interaction or cumulative rendering in this phase.

## Command and boundaries

Use the [M2.1 setup](M2.1.md#reproduction), then run:

```sh
python tools/benchmark_data_table.py --chrome "/path/to/chrome" --expansion-steps 10 --output ../m212-local.json
```

The initial 400-row view grows by 1,000 rows per action until the tenth action or the full dataset is reached.
Thus the small case ends at 2,000 rows and the other cases at 10,400. Each expansion uses the existing click
handler and includes forced layout plus two animation frames. Scrolling is measured at the final size; a
rendered numeric tail cell is focused and selected through the native Range API. Selection and keyboard
behaviour are not replaced by benchmark-only widgets.

CSV timing retains the M2.1 click-to-Blob boundary and excludes parsing, verification and disk download.
Every exported cell is still checked. A separate profiling trial collects two profiles: visual operations,
then a first full CSV construction without parsing/verification. The later verification export in that profile
trial is excluded from timing summaries. The unprofiled measured trials contain only one export.

Source/environment fingerprints, resets, frame-timing limits and whole-trial RSS accounting follow M2.1.
The same benchmark files must be used for before/after runs. Profile and measured results must produce the
same complete CSV. The benchmark remains informational and does not establish unique/private process memory.

## Lookup and correctness

`createIntervalLookup` sorts a copy of finite, nonempty intervals and uses binary search when they are disjoint.
It preserves the original interval references and half-open predicate (`x >= from && x < to`). Any overlap or
irregular bound retains linear search in source order. Nonnumeric/nonfinite queries retain the old predicate's
coercion. `tableModel` builds the lookup and resolves interval names once per core/layer for each invocation;
there is no persistent cache to invalidate when labels or bounds change. Scientific analysis and training
callers retain their existing paths.

Node regression compares object identity with the old predicate for explicit boundaries and irregular inputs,
then 100 deterministic generated interval sets on depth and converted age axes, using endpoint, midpoint and
random queries with exact equality. Browser regression separately checks the actual table and CSV against
explicit expected labels for disjoint unsorted intervals, first-match overlaps, gaps, touching endpoints,
age-to-depth conversion and an age-only core. Existing edit/restore, full export and selection checks also pass.

Local delivery checks pass: 181 Python tests (six skips: four unavailable Windows symlink permissions and two
optional ONNX/Torch checks), 127 Node tests, JavaScript types, version consistency, Ruff, ESLint (existing warnings),
standalone build and the complete Chrome smoke test. Required checks introduce no new dependency.

## Recorded comparison

The [V0.109 baseline](M2.1.2-v0.109-baseline.json) and [V0.110 indexed run](M2.1.2-v0.110-indexed.json) use
identical benchmark files and fixtures on Windows 11, Ryzen 7 7700X, Chrome 157.0.8103.40, Node 22.23.4 and
Puppeteer 23.11.1. Each contains one warm-up, five measurements per size and a separate profile trial. Every
CSV cell is verified in every trial; all three complete CSV fingerprints match before and after. Raw precision,
ranges, per-expansion times and RSS observations are retained. Summary statistics and expansion totals were
recomputed from the recorded trials.

Both reports precede the delivery commit and record a dirty tree with parent
`71f0735972d4f2c6c304ad92c04e696b409987f1`. Reconstruct the baseline with that commit's Git archive and the
three benchmark files delivered here (`benchmark_data_table.py`, `benchmark_data_table.mjs`,
`data_table_fixture.mjs` under `tools/`). The candidate uses the delivered app/package source, including V0.110
version stamps, and those same tools. Both aggregate source fingerprints were reproduced using the algorithm
in `benchmark.py::source_metadata`. No measured source or benchmark file was changed after its final run;
CRLF normalisation is part of that algorithm. Documentation and tests are outside the measured fingerprint.

Median times in ms:

| Total rows | Final DOM rows | Full CSV, before → after | Last expansion, before → after | All expansions, before → after |
|---:|---:|---:|---:|---:|
| 2,000 | 2,000 | 4.5 → 4.4 | 197.8 → 199.9 | 314.6 → 316.6 |
| 20,000 | 10,400 | 29.3 → 27.7 | 879.6 → 883.4 | 5,112.0 → 5,078.2 |
| 100,000 | 10,400 | 166.5 → 132.2 | 816.4 → 819.2 | 4,998.0 → 5,049.1 |

The large-case full CSV improvement is **20.6%**, below the predeclared **25%** target. Its measured range
changes from 163.1–169.0 to 125.4–153.5 ms. The correction is retained as a measured improvement with exact
output equivalence, but **M2.1.2 remains open**. It does not justify expanding this delivery into changes to shared
CSV formatting. The separate export profile now attributes its largest sampled JavaScript self time to
`core.js::toCSV`'s cell formatter; further work needs its own scoped acceptance and equivalence checks.

Opening medians change from 46.7 to 46.7, 55.0 to 56.0 and 86.4 to 90.3 ms. Edit-mode medians change from
62.0 to 59.1, 57.1 to 52.8 and 49.6 to 44.3 ms. The first expansion medians remain about 116.7–133.2 ms.
No opening or cumulative-expansion improvement is established. Selection remains correct at the final rendered
tail; scroll medians at 10,400 rows are about 80 ms, rather than the roughly 33 ms two-frame floor at 2,000 rows.
This does not measure pointer travel, all keyboard navigation, or a fully expanded 100,000-row DOM.

Whole-trial peak browser RSS medians in MiB change from 719.1 to 727.4, 2,253.4 to 2,413.3 and 2,269.6 to
2,275.6. In particular, the medium-case median is 7.1% higher, with overlapping ranges (2,101.0–2,419.6 before,
2,283.9–2,512.9 after). This sampler covers setup, the growing DOM and full CSV validation and does not isolate
the lookup or DOM allocation. No memory reduction or causal explanation of that variation is claimed.
Cumulative expansion and the unmet CSV target were the follow-up work at V0.110; the native table and its
controls remained unchanged.

## CSV formatter follow-up results (V0.111)

The [repeated V0.109 baseline](M2.1.2-v0.109-csv-baseline.json) and
[V0.111 candidate](M2.1.2-v0.111-csv.json) use the unchanged V0.110 benchmark tools, the same fixtures,
ten expansions, one warm-up and five measured repetitions per size, plus separate profile trials.
Both ran on Windows 11 / Ryzen 7 7700X, Chrome 157.0.8103.40, Node 22.23.4, Puppeteer 23.11.1 and
Python 3.12.4. Every cell is verified; the complete CSV fingerprints match at all three sizes, including
the original V0.109/V0.110 reports.

Median times in ms:

| Total rows | Full CSV, V0.109 → V0.111 | CSV reduction | Last expansion, before → after | All expansions, before → after |
|---:|---:|---:|---:|---:|
| 2,000 | 4.4 → 3.0 | 31.8% | 185.5 → 187.8 | 302.1 → 304.5 |
| 20,000 | 28.9 → 15.0 | 48.1% | 888.8 → 954.0 | 5,002.0 → 5,014.4 |
| 100,000 | 169.6 → 66.3 | 60.9% | 815.0 → 785.6 | 4,912.2 → 4,880.9 |

The large-case CSV ranges are 168.1–180.2 ms before and 65.3–67.0 ms after. The combined interval-lookup
and formatter changes exceed the existing 25% target. Against the original recorded V0.109 median of
166.5 ms, the reduction is 60.2%. These fixtures contain integer numeric measurements; the results do not
establish the same speedup for decimal-heavy projects or other machines.

`toCSV` sends integers directly to `String(value)` and retains `String(+value.toFixed(6))` for all other
numbers. Numeric output cannot contain CSV delimiters and bypasses text quoting checks. The text path retains
the original spreadsheet-formula escaping and quoting rules. The large export profile attributes 65.4 ms of
sampled self time to the old cell formatter and 8.0 ms to the new one; these are separate sampled trials,
not additional timing repetitions. No persistent cache or dependency is added to the application.

Three Node regressions check explicit numeric/quoting expectations and exact equivalence with a frozen V0.110
formatter over 10,000 deterministic mixed rows. Generated IEEE-754 bit patterns, their truncated values and
fractional values exercise subnormals, very large integers, rounding and nonfinite values. The browser table
regression edits a negative six-decimal value, checks its full CSV, restores it and checks the original export.

Opening medians are 47.3 → 47.1, 54.1 → 52.7 and 88.6 → 86.4 ms; edit-mode medians are
55.7 → 55.3, 53.2 → 58.3 and 49.5 → 51.0 ms. No opening, editing or cumulative-rendering improvement
is claimed. Whole-trial RSS medians in MiB are 721.8 → 719.3, 2,162.9 → 2,418.8 and
2,265.6 → 2,275.2. The medium-case median is 11.8% higher, with overlapping ranges
(2,079.4–2,468.5 before, 2,410.8–2,434.1 after); the large-case ranges also overlap. The sampler includes
setup and full CSV verification, so it neither isolates formatter allocations nor establishes a cause for
the variation. No memory reduction is claimed. Rendering the cumulative native DOM remains separate work.
