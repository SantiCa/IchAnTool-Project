# M2.2.3 navigation-preview experiment

## Predeclared contract

Authorised by the maintainer on 10 November 2026, after the [M2.2.2 profile](M2.2.md).
Editor: Codex. Verification: unit/browser regression and matched measurements; no independent reviewer assigned.

The experiment is a session-only checkbox, off by default. It affects only the section navigation strip.
Keep the current column/figure image renderer, source images, masks, working resolution, image/mask cache
budgets, depth mapping and scientific analysis definitions unchanged. Disable the checkbox to roll back;
promote/remove the flag only after acceptance criteria pass and the maintainer accepts that transition.

The new path may combine source-image and mask accumulation into one pass, retaining the legacy reduction
grid and compositing semantics as temporary intermediates. Cache only the displayed preview, separately from
column-image caches, with an 8 MiB LRU budget and weak section ownership. Release preview resources when the
flag is disabled or the project changes. Unsupported preview dimensions use the current path.

### Correctness and visual equivalence

- **Zero pixel tolerance:** base/overlay RGBA layers and the final displayed strip must exactly match the
  current renderer. Preserve its Float32 accumulation, Uint8Clamped rounding, alpha quantisation and canvas
  compositing. This is a display-path optimisation, not permission to approximate colours or remove traces.
- Cover original/enhanced images, overlays on/off, hidden/shown exclusions, opacity, class assignment/colour,
  overlap stacks, ROI changes, working-size changes, viewport resizing and cache invalidation/eviction.
  Verify deterministic wide inputs that require Float32 rounding, and input/resource bounds.
- Verify actual pointer click/drag positions against the existing navigation/depth mapping, within the
  M2.2.2 tolerance of 1e-9 working pixels (inverse-formula arithmetic only). Scientific arrays and exported
  mask pixels retain exact equality; verify deletion, Undo/Redo, save/reload and SVG/PNG regressions.
- Verify default-off behaviour, no flag in saved projects, session reset on reload, rollback and offline HTML.
  Visual comparisons run separately from timing/RSS trials so reference-image preparation cannot contaminate
  the experiment's cache residency or memory peak.

### Matched performance comparison

Use the [M2.2.2 command/fixtures/boundaries](M2.2.md#reproduce-the-profile), with identical benchmark tools on
V0.117 and the experimental application. Record separate source/tool fingerprints and input/result identity.
One warm-up, five measured trials and a separate CPU-profile trial per case; no simultaneous benchmark runs.

- At least 20% lower median `first_visits_total_ms` on the large case.
- No more than 20 ms added median resident-return latency, and no more than 10% added median whole-trial peak
  Chromium RSS on that case. Retain the same accounting limits and include export/reload verification.
- All exact scientific/input/image checks pass on both paths. Report every run, median/range, CPU sites and
  visual checks; claim improvements only for the measured workloads. The default path remains the rollback.

## Reproduce the comparison

Use the environment and fixtures in [M2.2.2](M2.2.md#reproduce-the-profile). For the recorded reference, create
a detached worktree at `250cba40ab7be10b755e1b3fc28020efdbcca9ce` (V0.117), then copy the following files from
this delivery into it: `tools/benchmark.py`, `tools/benchmark_images.py`, `tools/benchmark_images.mjs` and
`tests/e2e/navigation-preview.mjs`. Leave its application files unchanged. Make puppeteer-core 23.11.1
available to both trees; the recorded worktree is under the repository's ignored `dist/` directory, so Node
resolves the existing root installation. Run the commands sequentially, setting `PYTHONPATH` to each tree's
`src` before running its command:

```powershell
# V0.117 worktree
$env:PYTHONPATH = (Resolve-Path src).Path
python tools/benchmark_images.py --chrome "C:/Program Files/Google/Chrome/Application/chrome.exe" --warmups 1 --repetitions 5 --output ../M2.2.3-v0.117-legacy.json

# V0.118 tree, after the reference finishes
$env:PYTHONPATH = (Resolve-Path src).Path
python tools/benchmark_images.py --chrome "C:/Program Files/Google/Chrome/Application/chrome.exe" --nav-preview --warmups 1 --repetitions 5 --output docs/benchmarks/M2.2.3-v0.118-preview.json
```

`--nav-preview` enables the checkbox before timed project opening. It also adds one untimed, unsampled visual
trial per case. That trial prepares the reference and experimental gutter separately, waits for fonts and
layout frames, and compares all RGBA bytes initially and after every selection. Reference preparation cannot
alter the measured experiment's cache residency. The other timing, CPU, RSS and verification boundaries remain
those of M2.2.2. No other benchmark runs or test suites ran concurrently with these measurements.

For the additional public-core scientific comparison, serve the repository root and use isolated browser
contexts for the two applications:

```powershell
node tools/verify_navigation_equivalence.mjs http://127.0.0.1:8765/dist/m223-baseline/app/index.html http://127.0.0.1:8765/app/index.html "C:/Program Files/Google/Chrome/Application/chrome.exe"
```

This verification loads the public example through its ordinary button, sets 2 cm intervals and compares
complete masks, stacks, object assignments/predictions, interval arrays, settings and first-section original/
enhanced buffers, before deletion and after Delete, Undo/Redo and saved reload. Random section identifiers
are excluded; source order and every field listed above remain in the canonical hash. It measures no performance.

`250cba40ab7be10b755e1b3fc28020efdbcca9ce`, with all application/package files matching HEAD. The

The separate large navigation CPU profile replaces the reference `reduceRGBA` self-samples (1598.3 ms), its
photo/mask callbacks (268.7/658.7 ms) and `sectionCanvas` (145.5 ms) with `buildNavigationLayers` (1145.7 ms)

The default pixel/mask budgets stay at 900,000,000/500,000,000 bytes. The large navigation trace retains five

buffer totals are 614,400,000/860,160,000 bytes, excluding canvas/native allocations. This changes residency,
not the budget. Sampled Chromium RSS includes export/reload and varies with allocation/garbage collection;
the experiment does not claim lower total memory. Do not infer TIFF/16-bit, cold-cache or other-machine gains.

## Correctness and delivery verification

The three separate visual trials compare 31 complete 66-pixel-wide gutters, 1,548,822 displayed pixels in total,
with **zero differing RGBA bytes**. Full-resolution exported mask comparisons check 2,595,000, 6,144,000 and
15,360,000 pixels per trial. Unit tests independently reconstruct legacy Float32 reduction for small, irregular,
960-pixel and 16,384-pixel-wide inputs, including overlaps, excluded pixels and alpha quantisation. Cache tests
cover byte bounds, LRU eviction, replacement and disposal.

Browser regressions exercise original/enhanced pixels, overlays, exclusions, opacity, assignment/colour,
ROI, resolution and viewport changes. Additional retained-cache checks verify that changed inputs rebuild the
preview, unchanged inputs reuse it, invalidated canvases are disposed, unsupported dimensions fall back and
disabling/reset clears resources. Pointer click/drag preserves depth mapping within 1e-9 working pixels.
Column SVG is byte-identical with the flag off/on. Scientific state, session-only/default-off behaviour,
save/reload, rollback and standalone offline rendering pass.

Delivery checks: 188 Python tests passed (six optional/permission skips), 150 Node tests, JavaScript type
checking (894 existing diagnostics, 190 resolved baseline entries), Ruff, version consistency, full Chrome
smoke test, standalone build and standalone navigation regression. Visual inspection of the offline result
passes. No scientific formula, source image, mask, saved-project format or publication renderer changes.

The prototype meets its acceptance criteria and remains **off by default**. The maintainer decides whether
representative use supports promotion; the [roadmap](../roadmap.md) records that next checkpoint. Disable the
checkbox for immediate rollback. Tiled loading is deferred until a separately authorised workload justifies it.
