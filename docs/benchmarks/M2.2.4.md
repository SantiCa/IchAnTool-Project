# M2.2.4 navigation-preview promotion

## Scope and acceptance contract

The maintainer's request to continue on 10 November 2026 authorises the next roadmap phase: promote the
[validated prototype](M2.2.3.md) to the startup default. Editor: Codex; verification: matched measurements and
automated/browser regression. No independent reviewer is assigned. The maintainer has not reported a separate
trial on private projects; acceptance here uses public and deterministic synthetic workloads.

The optimised preview starts enabled. Keep a session-only checkbox to restore the previous renderer; reload
restores the startup default. Keep the existing column/figure renderer, image/mask budgets, analysis settings,
scientific definitions and saved-project format. Invalid saved regions and unsupported preview dimensions
must fall back to the existing path. Removing the rollback control is outside this delivery.

Before delivery:

- Repeat the three M2.2.3 workloads, timing boundaries and RSS accounting with identical tools on both paths
  of the candidate application. Run one warm-up, five measured trials and a separate CPU trial per case;
  run the reference and candidate sequentially, without concurrent test suites/benchmarks.
- The reference explicitly disables the preview before timed opening. The candidate must start enabled
  without changing the checkbox. Check the selected path in every timing/CPU result.
- Retain the large-case thresholds: at least 20% lower median first-visit time, at most 20 ms added median
  resident return, and at most 10% added median whole-trial peak Chromium RSS.
- Require exact source/enhanced buffers, masks, assignments, interval results, unaffected edit results,
  Undo/Redo, full-resolution exported PNG and saved/reloaded state. Display comparisons have zero RGBA-byte
  tolerance; pointer/depth inverse arithmetic retains the 1e-9 working-pixel bound.
- Verify current and legacy project import, startup/default behaviour, rollback, reload, invalid regions,
  fallback dimensions, unchanged column SVG, complete figure/save regressions and offline HTML.

## Reproduction

Use the [M2.2.2 environment and fixtures](M2.2.md#reproduce-the-profile). The application is the same on both
paths; the reference selects its retained legacy renderer. From the candidate tree, run these sequentially:

```powershell
$env:PYTHONPATH = (Resolve-Path src).Path
python tools/benchmark_images.py --chrome "C:/Program Files/Google/Chrome/Application/chrome.exe" --warmups 1 --repetitions 5 --output docs/benchmarks/M2.2.4-v0.119-legacy.json
python tools/benchmark_images.py --chrome "C:/Program Files/Google/Chrome/Application/chrome.exe" --nav-default --warmups 1 --repetitions 5 --output docs/benchmarks/M2.2.4-v0.119-default.json
```

`--nav-preview` remains supported for explicitly enabling previews on older experimental versions.
`--nav-default` instead requires the checkbox to start enabled and leaves it untouched. Legacy selection
explicitly disables it when the application starts enabled. Reports record requested mode and actual path;
the Python driver rejects a mismatch. Separate visual trials remain outside timing/RSS measurements.
The reference retains its session rollback through navigation, editing and export. The final verification
reload intentionally restores the candidate's enabled startup default on both paths, as the product does.
Whole-trial RSS includes that common reload stage; this is a comparison of the two session choices in the
candidate application, not a second V0.117 application measurement.

Fixture/scientific snapshots use source-order section indices instead of random storage IDs. Every scientific
field previously hashed remains present. This allows exact cross-path comparison of the public example as
well as deterministic fixtures, without changing projects or their stored IDs. Historical ID-bearing hashes
are not directly comparable; the [V0.118 canonical check](M2.2.3-public-equivalence.json) covers that earlier
comparison.

## Recorded results

The [legacy-session report](M2.2.4-v0.119-legacy.json) and
[startup-default report](M2.2.4-v0.119-default.json) measure the same V0.119 candidate working tree, on parent
commit `e1a11d9a0d6afb5dc7897eadb00b9ebc597bea36`. Both record application fingerprint
`d1162d1314e7066d75b22b37bd69a2f79347f758d8e02e36e486f2a951a607eb` and identical tool fingerprints.
`matches_head: false` is intentional: the version/default, fallback guard and interface text were uncommitted
during measurement. The delivered application has that fingerprint. The
[author audit](M2.2.4-source-audit.json) verifies source/tool identity, recomputes every median/range and checks
exact fixture/scientific equality across paths, including the public example. It is not independent review.
The reduction/cache module, shared analysis/image-processing modules and column renderer match V0.118 exactly.

Environment: Windows 11 10.0.26300, Ryzen 7 7700X (8 cores/16 logical CPUs), 31,850 MiB RAM; Python 3.12.4,

First-visit medians fall 33.4%, 35.3% and 33.4% respectively. The large case adds 0.1 ms median resident-return
latency. Its unrounded median peak RSS rises from 3287.5546875 to 3616.29296875 MiB: **9.99948%**, just below
the 10% limit of 3616.31015625 MiB. The formal memory criterion passes with less than 0.02 MiB headroom;
**no robust memory margin is established**. Individual peaks vary substantially, and the 25 ms process-tree
RSS sampling can miss between-sample peaks and double-count shared pages. This is not a general memory cap
or a guarantee for other projects/machines. Retain the rollback control; require further representative
memory evidence before considering its removal.

Large-case opening through two frames changes from 1316.8 [1295.2–1333.3] to 1265.7 [1053.6–1293.9] ms.
Separate large-navigation CPU samples attribute 1644.1 ms to the legacy reducer, 644.7/293.9 ms to its mask/
photo callbacks and 213.9 ms to `sectionCanvas`, versus 1233.6 ms to `buildNavigationLayers` on the default
path. These are sampled self-times from diagnostic trials, not components of elapsed medians. The CPU/RSS
accounting limits, worker attachment gaps and fixture scope remain those of M2.2.2. No TIFF/16-bit ingestion,
cold-cache, private-data or cross-platform performance claim is made.

## Correctness and delivery outcome

All fixture, source/enhanced-image, initial/scientific, saved, edit and mask-export identities match exactly
across paths. Three separate visual trials check 31 complete gutters, 1,548,822 displayed pixels, with zero
differing RGBA bytes. Full-resolution mask exports check 2,595,000, 6,144,000 and 15,360,000 pixels per trial.
The unchanged reducer retains the independent Float32/overlap/exclusion/alpha regression tests from M2.2.3.

Browser regression verifies startup enabled, session rollback, unchanged save status and no saved navigation
flag, enabled state after reload, source/overlay/exclusion/opacity controls, edits, ROI/resolution/viewport
changes, cache reuse/invalidation/disposal, unsupported/noninteger dimensions, invalid saved regions,
pointer/depth mapping within 1e-9 working pixels and exact unchanged column SVG. Additional ordinary imports
cover IchAnTool v2 JSON and a CorAnTool v3 `.corantool` package with image bytes and masks, followed by
byte-exact mask/result preservation and migrated saved reload. These checks also pass in the offline HTML.

Required checks pass: 188 Python tests (six optional/permission skips), 150 Node tests, JavaScript type checks
(894 existing diagnostics, 190 resolved baseline entries), Ruff, version consistency, full Chrome smoke test,
standalone build and offline current/legacy navigation regression. Visual inspection of the offline interface
passes. The complete smoke test retains its figure SVG/PNG, current/legacy reader and interrupted-save checks.

Delivered in V0.119. The preview is enabled at startup; its session control remains available. Scientific
definitions, working resolution, pixel/mask budgets, saved-project format and publication rendering retain
their existing contracts. M2.2.4 is complete against its declared criteria, with the narrow memory margin
recorded as a limitation. Future profiling of full-resolution/16-bit TIFF inputs requires a separately
authorised workload; removing the rollback control is not part of this delivery.
