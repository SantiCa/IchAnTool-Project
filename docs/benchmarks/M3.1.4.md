# M3.1.4 bounded row/class counting experiment

Follow-up: [M3.1.5](M3.1.5.md) evaluates and accepts the multi-row prototype. This report retains
the original single-row experiment and its failed acceptance.

Authorised on 11 November 2026. Editor: Codex; author verification; no independent reviewer assigned.

## Predeclared contract

First phase: Python label-mask counting, using NumPy already distributed with the package.
Prototype per-row histograms in blocks; retain the existing path by default and for overlapping layers.
Enable only with `SEDCORETOOL_EXPERIMENTAL_COUNTS=1`; unset it to roll back. Promotion and flag removal
require a subsequent acceptance decision. No JavaScript replacement in this phase.

Compare the public API on both corrected M0.1 fixtures at 2 and 1.37 cm using the unchanged
`tools/benchmark_analysis.py`: one warm-up, five fresh-process measurements and separate CPU diagnostics.
Target at least 20% lower median Python API elapsed time in every case/interval, and at most 10% higher
median whole-worker peak RSS for each case. Use matched environment and tool hashes. These RSS measurements
include setup/verification, not just allocations. Histogram temporaries must be bounded independently of
image height. Require identical Python fingerprints, unchanged inputs, exact boundaries/indices/missing
values, original 1e-9 JavaScript tolerance, legacy regression, configurable schemes and overlap/exclusion tests.
If targets fail, retain the default and publish the failed outcome. No speed claim before comparison.

## Outcome (V0.122)

The experiment is complete; performance acceptance fails and the established path remains the default.
[Baseline](M3.1.4-baseline.json), [experiment](M3.1.4-experiment.json) and
[comparison](M3.1.4-comparison.json) retain per-trial results, medians/ranges, CPU diagnostics, source/tool
fingerprints and environment. Both runs use the same Python/NumPy/pandas/Pillow and browser tools.
The baseline measures clean V0.121; the candidate measures that commit with only pipeline.py modified.
Version synchronisation to V0.122 follows measurement. The candidate was enabled by
`SEDCORETOOL_EXPERIMENTAL_COUNTS=1` in the parent shell, inherited by Python workers.

|---|---:|---:|---:|---:|---:|

| Public | 1.37 cm | 571.3 | 286.8 | 49.8% | 139.68 / 141.23 |
| Synthetic | 2 cm | 553.6 | 575.3 | -3.9% | 322.39 / 322.50 |
| Synthetic | 1.37 cm | 562.0 | 591.5 | -5.2% | 322.39 / 322.50 |

The public comparison is confounded by different background load: unchanged JavaScript cold medians
also fall substantially between runs. It establishes no reliable public-case speedup attributable to
this implementation. Synthetic results alone already fail the predeclared latency requirement.
RSS stays within the 10% threshold in both cases. No default promotion is justified.

All input, JavaScript result and Python result hashes match exactly between runs, at both interval
sizes. Both complete/scientific-parity flags pass, including all fourteen trial pairs per run and
normal fixture deletion/save/reload. Cross-language tolerance remains 1e-9; BI/ii/missing values match.

The candidate loops over rows and column chunks, selecting valid labels and accumulating NumPy
bincounts. Scratch is bounded to 65,536 pixels per chunk (selected labels plus integer conversion);
the retained int64 histogram occupies `8 * rows * (classes + 1)` bytes. It does not depend on total
image width. The output and existing input/layer buffers remain separate from that scratch bound.
No new dependency is introduced. Overlapping boolean layers use the existing implementation.
The per-row Python loop is a plausible source of overhead on the four-class synthetic fixture;
this is an inference, not a separately isolated measurement.

Validation: 217 Python tests with six optional/permission skips on both default and enabled paths;
153 Node tests, types, Ruff, version consistency and standalone build. Randomised exact API comparison
covers exclusions, absent classes, custom scheme precedence, partial/fractional bins and overlap fallback.
No interface or saving changes; browser fixture preparation checks the existing save/reload workflow.

Next candidate: separately authorise a multi-row bounded histogram prototype and a counterbalanced
comparison to reduce background-load confounding. Keep this flag until that decision; remove the
prototype if superseded or rejected. This phase does not optimise JavaScript counting.
