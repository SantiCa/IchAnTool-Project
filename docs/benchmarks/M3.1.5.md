# M3.1.5 multi-row histogram experiment

Authorised by the maintainer on 11 November 2026. Editor: Codex; author verification, no independent reviewer.

## Predeclared contract

Replace the opt-in single-row histogram with bounded multi-row NumPy histograms. Keep the established
per-class reductions as the default and retain overlap fallback. Encode each pixel as
`local_row * (classes + 1) + label`; use one bincount per block, then reshape to row/class counts.
Limit blocks to 65,536 pixels and at most 64 rows, including column chunks for wider inputs.
No dependency changes. Existing `SEDCORETOOL_EXPERIMENTAL_COUNTS=1` selects the new prototype;
unset it to roll back. Promotion and removal of the flag remain a separate decision.

Compare the public analyze_mask API on the two edited M0.1 fixtures at 2 and 1.37 cm. Prepare through
normal browser deletion/save/reload, require original input fingerprints, and verify both modes against
the browser and the corrected Python fingerprints. Require exact Python arrays/fingerprints including
indices and missing values, and retain the 1e-9 cross-language tolerance. Keep legacy, overlap, exclusion,
custom scheme, partial-bin and noncontiguous-input regressions.

Run one warm-up pair followed by six measured fresh-process pairs per case, alternating AB/BA order
(three of each measured order). Decode/remap outside API timing. Report all elapsed/CPU times, paired
ratios, medians/ranges and whole-worker peak RSS using the existing 25 ms sampler and actual worker PID.
Target at least 20% lower median API time at each case/interval and at most 10% higher median peak RSS
per case. Also require median paired time ratios <=0.8. Record source/tool hashes and reject mutations
during the run. Browser analysis is checked once per case; no browser speed claim.

If NumPy passes, stop this sequence without adding Rust. If it fails, evaluate a separately bounded
Rust counting kernel under the same scientific and performance contract; retain Python intervals/indices.
No performance result or acceptance has been assumed in advance.

## Reproduction and measurement boundaries

```sh
python tools/benchmark_counts.py --chrome "/path/to/chrome" --output docs/benchmarks/M3.1.5-v0.123.json
```

Use the existing benchmark dependencies (Python analysis dependencies, psutil, Node 22, puppeteer-core 23,
and Chrome). No application dependency is added. The driver explicitly clears or sets the experiment
variable inside each worker and records the mode, preventing inherited flags from selecting both paths.
One warm-up pair precedes six measured pairs per case; measured order is BA, AB, BA, AB, BA, AB.
Each worker decodes/remaps the same snapshot before measurement. Timers cover one public API sweep over
all sections, including validation, counting, binning, indices and DataFrames; they exclude input preparation,
serialization and startup. Each setting also repeats per-section analysis outside the reported full-sweep
timer and verifies identical output. Both interval sizes run in the same worker, 2 cm first. CPU time is
process_time, not a sample profile; no new CPU profiler run is used in this comparison.

The existing 25 ms RSS sampler identifies the actual Python worker PID, including Windows launcher children.
RSS covers the complete worker lifetime, including decoding and verification. It is not isolated kernel
allocation memory, and short peaks can be missed. Browser measurement prepares the edited snapshot through
normal deletion/save/reload, verifies original input/result fingerprints and computes both interval sizes
once per case. Browser cold/cached/direct-stage checks remain in that driver; browser speed is not compared.

## Resource bounds and validation

Blocks use `min(64, max(1, 65536 // max(1, width)))` rows. For widths above 65,536, one row is processed
in column chunks. The encoded and selected integer arrays each contain at most 65,536 elements; the
bincount output contains at most `64 * (classes + 1)` elements. Conversion and broadcasting may retain
another block-sized integer temporary. Scratch is bounded by block dimensions, while the retained int64
row/class histogram is `8 * rows * (classes + 1)` bytes. Original masks, valid arrays and DataFrames are
outside this scratch estimate. Empty-width blocks produce zero counts without bincount calls.

Regression tests verify exact integer counts against independent class-by-class sums for strided arrays,
255 classes, zero classes, very wide inputs and partial blocks; they check actual bincount input/output
bounds and a reduction from 145 row calls to three block calls. Complete API comparisons cover exclusions,
fully excluded/no-data bins, boolean masks, fractional and partial bins, absent classes, overlapping layers
and custom index precedence. Legacy CSV and half-row regressions pass. Benchmark acceptance tests reject
latency or memory failures.

Checks pass on both default and enabled paths: 223 Python tests with six optional/permission skips;
153 Node tests, JavaScript types, Ruff, version consistency, whitespace and standalone build.
No interface or save implementation changes: the normal browser preparation/save/reload checks above
cover the affected benchmark setup; the full interface smoke suite is not repeated.
