# M2.1.3 gated Data table viewport experiment

## Scope and acceptance declared before implementation

The maintainer authorised this phase on 10 November 2026. Codex is the editor. Keep the native table as the
default; a session-only **Visible rows only (experimental)** checkbox enables the experiment. No stored
project setting, saved-data format or scientific definition changes. Disabling the checkbox rolls back to the
native table. Promotion and removal of the flag require passing the criteria and the maintainer's acceptance.

- Reuse the deterministic 2,000/20,000/100,000-row M2.1 fixtures, ten Show more actions, one warm-up and five
  measured trials per case, plus separate profiles. Compare the V0.111 native path and the candidate's flagged
  path with identical benchmark tools. Require at least 50% lower median total expansion latency at 100,000 rows.
- Prepare/render a bounded visible window with overscan when no selection is active, including after scrolling
  to the last unlocked row. Keep global row numbers, core/column/layer order, total counts and the existing
  400-row initial / 1,000-row expansion limits. CSV always includes every selected row, independent of the window.
- Require identical full CSV data fingerprints. Verify edited decimals, missing values, calculated/manual
  columns, empty and age-only cores, core/layer filters, restore, switching views/projects and disabling the flag.
- Preserve native text selection within and across rendered rows. Retain the contiguous selected range during
  scrolling, even when it exceeds the normal window budget; release it when selection collapses. Record this
  exception and exercise pointer selection across a moving window before claiming full selection parity.
- Commit a focused numeric edit before scrolling it out of the window. Preserve Escape cancellation, Enter and
  vertical arrows; add Tab/Shift+Tab, PageUp/PageDown and Ctrl/Cmd+Home/End navigation across window boundaries.
  Keep arrow-left/right and text-selection modifiers available for native text editing.
- Record opening, editing, selection, final scrolling, full CSV and whole-trial sampled browser RSS. Do not
  infer isolated memory savings from RSS that also includes fixture preparation and full CSV verification.
  Run all delivery checks and browser regressions. Keep performance thresholds informational, outside CI.

## Measurement boundaries

Keep M2.1.2's click-to-forced-layout-and-two-frames visual timing and click-to-Blob CSV timing. Record logical
unlocked rows separately from mounted DOM rows; spacers are not data rows. Scrolling must wait for the window
update and verify the final logical row, rather than merely setting scrollTop on a tall placeholder.

Before timing, both modes open the Data table through its normal control and return to Section mode. The
flagged case also enables the checkbox during this configuration step. Each timed opening therefore re-enters
a configured session; its results must not be compared directly with the first-opening numbers from M2.1.2.
Native and flagged trials otherwise use identical tools and timing boundaries. Profiles are separate trials.

The model should prepare only the requested range and must not retain a full prepared-row cache. Native
selection can retain extra DOM rows; a selected range spanning a large part of the table can therefore incur
the native table's preparation/rendering cost. The experiment does not change export allocation behaviour.

## Reproduction

Use the [M2.1 environment and fixtures](M2.1.md#reproduction). From the measured checkout:

```sh
python tools/benchmark_data_table.py --chrome "/path/to/chrome" --expansion-steps 10 --output ../native-local.json
python tools/benchmark_data_table.py --chrome "/path/to/chrome" --expansion-steps 10 --viewport --output ../viewport-local.json
```

The recorded baseline uses V0.111 plus the three V0.112 benchmark files (`benchmark_data_table.py`,
`benchmark_data_table.mjs`, `data_table_fixture.mjs` under `tools/`). The candidate uses the same files with
`--viewport`. Keep the native/default control flow when repeating the baseline; do not emulate the flag with
test-only rendering. The CLI keeps its earlier default of one expansion unless `--expansion-steps 10` is supplied.

## Recorded results (V0.112)

The [V0.111 native baseline](M2.1.3-v0.111-native.json) and
[V0.112 flagged experiment](M2.1.3-v0.112-viewport.json) ran on Windows 11, Ryzen 7 7700X,
Chrome 157.0.8103.40, Node 22.23.4, Puppeteer 23.11.1 and Python 3.12.4. Each has one warm-up and
five measured runs at every size, plus separate visual/export profile trials. Every full CSV cell is checked
against the deterministic fixture. All three CSV data fingerprints match the baseline and previous M2.1 reports.

Median visual times in ms:

| Source rows | Final available rows | All expansions, native → flagged | Reduction | Last expansion, native → flagged | Final scroll, native → flagged |
|---:|---:|---:|---:|---:|---:|
| 2,000 | 2,000 | 299.5 → 66.6 | 77.8% | 183.0 → 33.3 | 32.7 → 33.2 |
| 20,000 | 10,400 | 5,952.9 → 332.9 | 94.4% | 1,061.0 → 33.3 | 98.5 → 33.2 |
| 100,000 | 10,400 | 5,745.6 → 332.9 | 94.2% | 988.6 → 33.2 | 95.7 → 33.3 |

The 100,000-row total-expansion range is 5,473.3–5,943.3 ms natively and 332.6–333.3 ms flagged,
exceeding the predeclared 50% reduction target. The small fixture needs only two expansions to reach its end;
the medium/large fixtures use ten. The roughly 33 ms floor includes the required two animation frames and is
not a measurement of JavaScript work alone. The final scroll verifies the last available logical row and the
bounded window after the scroll callback has run.

| Source rows | Final DOM data rows, native → flagged | Full CSV median (ms), native → flagged | Whole-trial peak RSS median (MiB), native → flagged |
|---:|---:|---:|---:|
| 2,000 | 2,000 → 36 | 3.0 → 3.5 | 724.9 → 504.5 |
| 20,000 | 10,400 → 36 | 20.0 → 17.9 | 2,255.4 → 599.8 |
| 100,000 | 10,400 → 36 | 84.3 → 71.9 | 2,299.4 → 717.6 |

Flagged trials mount 37 rows at the initial and first-expanded positions and 36 after final scrolling,
independently of source size; spacers are excluded. The model has no full prepared-row cache. Whole-trial
RSS is lower on these recorded workloads, but it includes setup, DOM, full CSV construction and verification.
Its large-case range is 2,278.6–2,314.4 MiB natively and 706.6–741.5 MiB flagged. This does not isolate DOM
allocations, measure private/unique memory or predict memory when a large native text selection is retained.
The [M0.1 RSS sampling definitions and limitations](M0.1.md#measurement-boundaries) apply unchanged.

Configured-session opening medians are 40.5 → 12.5, 47.7 → 20.1 and 78.1 → 50.5 ms. Editing-mode rebuilds
are 50.9 → 33.0, 57.4 → 32.2 and 50.2 → 28.5 ms. Initial text selection stays near 33 ms. Final selection
is 32.4 → 33.4, 58.7 → 33.3 and 58.3 → 33.3 ms. The small CSV median is 0.5 ms higher; no CSV improvement
is attributed to this rendering experiment. Larger CSV medians are lower here, with identical formatting code
and output, but the measurements do not establish a cause for that variation. Full raw ranges and profiles
are retained in the reports. No performance thresholds are added to CI.

## Correctness, packaging and limits

Three Node tests cover explicit geometry boundaries, invalid arguments and generated offsets/heights at all
fixture scales. Browser regression counts numeric reads while enabling the flag: only mounted rows times six
numeric columns are read. It verifies 28 px row heights, sticky headers, narrow-window horizontal focus,
native Range selection retention/release and pointer dragging while wheel-scrolling across the moving window.
The retained drag range contains every intervening logical row. This exercises the declared interaction
contract, rather than establishing parity for every browser, assistive technology or selection gesture.

The browser also verifies decimal edits committed on scroll or leaving Data mode, Escape, Enter/arrows,
Tab/Shift+Tab across core boundaries, PageUp/PageDown, Ctrl+Home/End, cell/all restoration, calculated/manual
columns, missing values, core/layer filters, empty and age-only cores, view/project changes, repeated controller
disposal and rollback to the native table. Rich inserted markup retains the same text and cannot expand a row.
A separate page confirms the flag starts disabled. An extended case unlocks all 100,000 rows, reaches row
99,999 and navigates between the first and last cells with fewer than 100 data rows mounted.

Visual inspection checked the generated layout. A browser check of the generated standalone HTML opened
directly through `file://`, enabled the flag, unlocked all 100,000 rows, verified bounded rendering at the last
row and hashed its complete exported CSV against the recorded large-case fingerprint. That check captures
the normal CSV Blob and hashes its data directly; the bundled application loads its table code inline.

Required checks pass: 181 Python tests (six skips: four unavailable Windows symlink permissions and two
optional ONNX/Torch checks), 133 Node tests, JavaScript type checks, version consistency, Ruff, the standalone
build and full Chrome smoke test. The extended viewport regression also passes independently. There are no
new application dependencies. The scientific algorithms and CSV data remain unchanged.

The flag remains disabled by default. Large selections intentionally retain extra rows and can approach the
native table's cost. Fixed widths may clip long displayed text; selection and CSV keep the complete text.
The measured baseline expands only to 10,400 rows, with a separate correctness check at 100,000; it is not a
performance claim for every fully expanded size or other machines. Promotion remains the maintainer's decision.
